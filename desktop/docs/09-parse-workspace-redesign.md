# 解析笔记工作台改版方案

状态：已实现主要流程，自动验证见文末；原生窗口与视觉验收待连接环境。用户已选择默认流程：先解析并展示预览，再点击下载。

当前实现入口：`features/parsing/Workspace.tsx`、`InputComposer.tsx`、`NotePreview.tsx`、`features/downloads/DownloadPanel.tsx`、`DownloadOptions.tsx`、`AdvancedOptions.tsx`。一条和多条链接复用 collection 作业，旧单笔记记录与 `/parse/collections/:id` 地址保留查看入口。

## 当前用户怎么使用

| 场景 | 当前操作路径 | 问题 |
| --- | --- | --- |
| 单条笔记 | 单笔记 Tab → 填链接/ID、选账号 → 开始解析 → 最近解析表格 → 查看笔记 → 下载笔记 → 配置抽屉 → 手动预览计划 → 创建任务 | 结果与输入分离，连续跳转，正常下载也必须理解完整配置 |
| 批量笔记 | 批量 Tab → 多行链接/分享文本或文本导入 → 账号分配/范围筛选 → 开始 → 作业页 → 选结果 → 下载抽屉 → 预览 → 创建任务 | 单条与批量使用两套表单、作业和结果界面 |
| 用户主页 | 用户 Tab → 主页/ID → 账号与范围筛选 → 用户作业 → 选笔记 → 下载抽屉 | 页数、并发、缓存、账号池等技术参数暴露过早 |

关键实现入口：`features/notes/parse-route.tsx`、`single-panel.tsx`、`features/parsing/InputPanel.tsx`、`result-route.tsx`、`features/downloads/CreateDrawer.tsx`、`SelectionFields.tsx`。

### 已有参数的真实含义

- 解析参数控制收集范围：账号、用户页数/笔记总上限、类型、日期、关键词、是否只收集包含 LivePhoto 的笔记、缓存和解析并发。
- 下载参数控制保存内容：图片/视频/实况动态、视频清晰度与编码、图片变体、LivePhoto 导出方式、目录、历史过滤、已有文件处理及附加文件。
- 解析页的 LivePhoto 筛选会筛掉整条笔记；下载的 LivePhoto 导出控制静态图和动态视频。两者不能使用同一个模糊开关。
- 当前视频候选已经在 `xhsapi.SortVideoStreams` 按可用 URL、像素数、帧率、编码及同编码码率排序。`VideoBest` 复用这个顺序，不需要重写已有排序。
- 现有视频“尺寸筛选”使用长边像素，不能直接把 `max_long_edge=1080` 标成 1080p。
- 现有 `VideoSelection` 同时约束主视频和实况动态；新的主视频清晰度/编码选择需要避免意外排除实况动态。
- 当前 `BuildPlan/BuildPlans` 返回下载项、大小和警告，但历史去重在执行阶段检查。界面不能用现有预览假称某些文件已经确认可跳过。

## 目标流程

粘贴链接 → 解析 → 在当前页面查看结果 → 选择内容与规格 → 点击下载。

只在解析完成后展示下载选项。首次打开只需要输入和解析账号。一个入口接受一条或多条笔记链接；用户主页保留一个独立入口，避免用户 ID 与笔记 ID 的歧义。

解析保留完整媒体候选。改变下载规格无需重新解析。解析成功也不会自动创建下载任务。

- 单条结果直接展示预览；下载区靠近预览，在宽窗口中位于右侧。
- 多条结果使用封面列表，点击一条查看同样的预览。进入选择模式后出现批量选择栏，右侧选项应用于已选笔记。
- 应用最小尺寸为 1280×720，默认 1440×900；该宽度内预览与下载区保持双栏，预览可滚动、下载区就近停靠。网页窄窗口回退到上下排列。
- 播放视频由用户点击触发；缩略图懒加载。没有结果时不展示空下载侧栏，不预填假封面或假统计。
- 整体延续中性背景、白色内容面、轻边框与蓝色主操作。标题、输入、媒体和主按钮建立层级；不加入统计栏、装饰步骤条或重复说明。

### 作者基础信息（用户追加要求）

- 单条结果预览在标题附近展示作者真实头像、昵称、可复制的用户 ID，以及作者主页入口；昵称作为主要文字，ID 使用次级字号。
- 批量结果每条展示小头像和昵称，展开预览后显示完整基础信息，避免在列表重复铺开长 ID。
- 输入区域的“解析账号”与结果区域的“作者”分别标注。作者信息取自该次笔记响应，保持与当前解析快照一致。
- 现有 `xhsapi.NoteUser` 已包含 `ID`、`Nickname`、`AvatarURL`，`decodeNoteUser` 读取响应中的 `user_id`、`nickname`、`avatar`。完整笔记快照可直接复用这些字段；批量轻量摘要需要补上作者 ID、昵称与头像地址。
- 头像懒加载，缺失或加载失败时使用昵称首字占位；未知昵称如实标注。点击作者头像/昵称或主页入口可以查看作者主页。
- 普通页面只展示基础身份信息，完整内部字段、访问 token 和原始 JSON 留在相应数据边界中，不为展示头像另取整份用户资料。

## 参数怎样让用户选

| 用户看到的项目 | 普通选择方式 | 默认与边界 |
| --- | --- | --- |
| 保存内容 | 按实际内容显示“图片”“视频”“笔记正文”选项 | 图片/视频默认选中，正文可选；没有视频就不展示视频参数 |
| 视频清晰度 | 自动最佳；解析后出现实际可用的分辨率，旁边标实际宽×高 | 默认自动最佳；1080p/720p 只是有依据的辅助标签，未知尺寸如实展示 |
| 视频编码 | 自动推荐；实际返回的 H.264、H.265/HEVC、AV1 等 | 默认自动推荐；清晰度与编码联动，只允许可用组合；未知编码保留在更多规格中 |
| LivePhoto | 照片＋动态、只保存照片、跳过实况内容 | 默认照片＋动态；仅在结果确有实况时出现；“跳过”明确排除该实况的静态和动态，不影响普通图片 |
| 保存位置 | 展示当前文件夹，点击更改 | 继承设置中的下载位置；支持保存预设，目录是否随预设保存保持明确 |
| 更多选项 | 折叠区/按需抽屉 | 全部清晰度、每编码最佳、逐项候选、HDR、帧率、图片格式、命名、覆盖/复用、重试、JSON/raw 等 |

选择规则：

1. 单条笔记以实际候选生成可选组合。主视频选择与实况动态选择分开处理，改变主视频编码不会静默取消实况动态。
2. 批量以通用策略应用于各条笔记，不把某一条笔记的 candidate ID 应用到其他笔记。精确选流通过进入该笔记单独设置。
3. 批量清晰度提供自动最佳及清晰度上限策略。无法满足时明确汇总受影响笔记，允许调整或跳过，不偷偷选择更高规格。
4. 同一编码和分辨率仍可能有多个帧率/HDR/码率候选。普通选择使用既有排序挑一份，更多规格展示完整候选。
5. 视频与图片均保存接口提供的原始媒体；选择 H.264 或 JPG 表示选择已有格式，不承诺转码、升清晰度或生成新媒体。
6. LivePhoto 的照片＋动态保存为配对文件和索引，不标成已经合成为苹果相册可识别的 LivePhoto。
7. 没有可保存内容时禁用下载，并指出需要选择什么。只勾选不支持的格式/清晰度时不给出“可下载”的假状态。
8. 默认主操作下载一份推荐规格。导出所有编码/所有清晰度属于高级选择，预览会反映额外媒体数量。

## 解析参数的展示时机

- 笔记链接：输入、导入文本、解析账号；单条/批量由输入数量识别，不再要求先切换两个功能相同的 Tab。
- 用户主页：额外展示“本次最多解析 100 条”与“筛选”，明确这是整个作业的合计上限。日期、笔记类型、关键词进入筛选面板。
- 账号选择显示头像、真实昵称和状态。默认使用已启用的默认账号；已失效/受限/禁用账号不作为默认可用选项；待校验状态可直接校验。
- 账号池、解析并发、缓存、原始响应保留等进入高级解析选项，初始页面不展开。
- 输入识别给出实际可确认的条目数和无效行；短链接的最终目标及真正去重结果由后端确认，前端不提前声称完成去重。
- 切换模式不丢输入草稿；混合笔记与用户主页输入时说明分开解析。保留现有输入大小和来源数边界。

## 结果、下载与反馈

- 解析进度在结果区域就近显示。发现过程总量未知时显示已发现/已完成数量，避免错误百分比。
- 单条成功立即给出预览，失败在该条显示原因和重试操作。批量部分失败不阻挡成功笔记下载，只重试失败项。
- 下载策略、内容、目录变化后自动重新生成轻量计划，短暂防抖，并忽略旧请求结果。用户无需额外点击“预览下载计划”。
- 计划生成中禁用下载，完成后展示一行真实摘要，例如“8 张图片 · 8 段实况”；已知大小与未知大小分开表达。辅助索引/JSON 在展开明细中展示，计数不混称媒体文件。
- 当前接口只提供规划信息时，摘要只显示实际计划；只有后端验证确实可复用的文件，才显示已确认跳过的数量。
- 点击下载使用该解析快照及本次配置；请求 ID 保持幂等，按钮防重复提交。成功后就近显示“已加入下载队列”与查看任务入口，保留预览供继续整理。
- 离开解析页后后端任务继续运行；返回时按作业 ID 恢复结果。不要用组件生命周期触发自动下载。
- 批量每次最多下载 200 条，选择达到上限时提示；不限制已有 1000 来源解析能力，也不偷偷拆分并连续提交下载。

## 需要补齐的实现边界

| 内容 | 实现方式 |
| --- | --- |
| 统一一条/多条笔记输入 | 复用 collection 的分享文本/短链处理，为 1 条和多条提供一致展示；保留旧单笔记 API 与记录兼容 |
| 预览结果 | 批量接口增加对应解析快照的轻量摘要：封面、作者 ID/昵称/头像、类型、媒体数量；完整正文和候选按需获取，避免每行获取整个快照 |

| 下载参数复用 | 解析结果、笔记库、笔记详情使用同一套普通/高级选择组件与配置转换，避免三个地方默认不同 |

## TitleBar 双击修复计划

按 Windows 桌面惯例，双击标题栏切换最大化/还原。

已确认：窗口是 Frameless，标题栏通过 `--wails-draggable: drag` 声明拖拽区域；`AppShell` 没有双击处理。锁定的 JS runtime 中，显式 `wails:drag:doubleclick` 处理仅用于 macOS，Windows 的拖拽事件路径也可能抑制 click/dblclick。这些是代码证据，尚未在原生窗口复现。

已加入标题文字/空白双击的最大化与还原处理，排除交互控件，RPC 执行中防重复调用；监听 Wails 的窗口状态事件并更新按钮。DOM 回归覆盖调用路径，真实 Windows 拖拽和最大化仍需原生验收。

实施时：

- 为 Windows 标题文字及空白拖拽区接入现有 `Window.ToggleMaximise`，依据运行时事件路径选择单一触发方式，防止被拖拽捕获吞掉或重复切换。
- 侧栏折叠、最小化、最大化、关闭等控件及其子元素排除在双击区域之外。
- 同步窗口状态，最大化后图标和提示显示“还原”。拖拽、窗口边缘缩放和已有窗口按钮继续按原生行为工作。
- 回归测试覆盖空白/文字双击只触发一次，以及控件双击不触发；原生验收覆盖最大化、还原、拖拽和缩放。DOM 测试不能代替真实 Windows 验收。

## 已实现的边界

- 当前页预览显示作者头像、昵称、用户 ID、主页入口、正文、图片及点击后加载的视频/实况；批量摘要直接读取其对应快照，避免最新作者投影覆盖旧解析结果。
- 普通下载选项与高级选项在工作台、笔记库和笔记详情共用。清晰度按实际宽×高选择，批量上限使用短边规则；主视频与实况动态可独立选择，新增实况排除模式和独立静态保存开关，旧字段省略时保持原语义。
- 轻量预览不传 signed URL 或 inline 文件正文，响应总量限制 8 MiB；未知大小如实显示。没有匹配内容时可调整设置，批量可跳过受影响笔记。
- 修改配置后自动生成计划，旧响应不会启用下载按钮；下载只在明确点击时创建，网络重试复用请求 ID，成功后显示就近状态与查看任务入口。
- 页面通过作业 ID 恢复结果，模式草稿保持，后台解析与下载继续运行；下载单次最多 200 条。
